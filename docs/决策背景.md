## 一、支付通道：试过什么，结论是什么

**这一节能省你至少两天的调研。**

### 已确认走不通的

| 方案 | 为什么不行 |
|---|---|
| **微信支付 / 支付宝 官方商户** | 个人拿不到。微信《提交申请单 API》2025.03.26 明确：「本接口不支持进件个人小微商户」 |
| **免签支付**（个人收款码挂监控） | **2025 年有判刑案例（4 年）**。绝对不做 |
| **独角数卡** | 项目已归档，没人维护 |
| **知识星球** | 抽成 10–20%，且不支持发授权码 |
| **小鹅通** | ¥6800+/年，太重 |
| **面包多 Pay** | 半废弃状态 |

### 个人能用的（按推荐度）

| 方案 | 费率/成本 | 状态 |
|---|---|---|
| **个体户执照 + 支付宝当面付** | 0.6% | **最优解**。办执照 1–3 天免费，签当面付后全自动。代码已写好 |
| **XorPay** | 1.2% + ¥100 开通 | 可用，但**支付宝单笔限额 1k**，¥1999 那档不能用支付宝 |
| **虎皮椒** | — | 收紧中，要 30 天 ICP 备案 |
| **爱发电** | 6% | webhook 无签名，要自己补校验 |
| **收款码 + 人工确认** | 0 | **当前方案**。能用，但不是全自动 |

### 当前实现

```
PAY_PROVIDER = "mock"     ← 站内下单走模拟支付
真实收款 = 用户扫收款码 → 点「我已付款」→ 管理员在 /admin 确认 → 自动开通
```

`PAY_PROVIDER=alipay` 的代码（RSA2 签名验签）**已经写完并测过 17 项**，
只等个体户执照下来，改一行配置就能切。

### ¥1999 那档的真实约束

XorPay 的支付宝单笔限额 1k，所以 **¥1999 必须用微信或当面付**。
如果用户问「为什么不能一次性买」，这是原因。

## 二、内容的处理原则（这条最重要，涉及法律风险）

**这个项目的内容不是抄的，是用三层结构重构的。**

### 三层结构

```
第一层：从逐字稿学「方法」
  └─ 学它怎么组织一章：先说处境，再给判断，再给史料，最后给失效边界
  └─ 只学结构，不搬字句

第二层：从 _史料库 自己找史事
  └─ 4386 卷一手史料，自己检索
  └─ 引用必须标出处（《史记·淮阴侯列传》这种）

第三层：逐字稿只用它的章节结构，正文自己写
  └─ 37 万字全部重写
```

### 用户的原始要求（原话）

> 「不是素材，是说话方式，是六爻付费讲解内容的版权，你可以根据渤海小吏、梁东、韩鹏杰的内容
> 然后加上历史事实，来新构建出你对于周易六十四卦的讲解版本。是这个逻辑，不是让你抄，是让你重构」

> 「从逐字稿学他的方法 / 从 _史料库 自己找史事 / 逐字稿只用它的结构，正文自己写」

### 红线

- ❌ **不要直接引用任何现当代作者的原文**
- ❌ **不要用「我认识一个人，三十四岁」这种个人化叙事模仿**
- ✅ 引用古籍原文照抄没问题（《史记》《汉书》《资治通鉴》都是公有领域）
- ✅ 自己的解读、白话、判断，随便写

### 如果 MiMo 要扩写内容

**必须先读 `content/写作规则.md`**，那里有完整的写作规范。

## 三、产品定位的三个判断（会影响每一个文案和功能）

### ① 用户是「求助者」，不是「读者」

```
错的定位：一个很全的周易网站，来读书
对的定位：我现在卡住了，来要个判断
```

**推论**：
- 首屏要先给「结果长什么样」，不是先给「内容有多少」
- 「384 条」「64 卦」这种库存数字没有说服力
- 「你在哪 / 该做什么 / 什么情况下不适用」才是价值

### ② 文案的合规红线：不写「算卦 / 算命 / 预测 / 吉凶」

```
原因 1：支付宝、微信都禁止「封建迷信」类目，写这些签不下支付
原因 2：服务条款里写的是「不是占卜、算命或预测服务」，文案不能自相矛盾
```

**用词替换表**：

| 不要写 | 改成 |
|---|---|
| 测卦、占卜、算一卦 | 处境自测 |
| 预测、吉凶、运势 | 处境、阶段、判断 |
| 灵验、准不准 | 有没有对上、是不是这个情况 |

**玩法其实一样，只是换了个名字。**

### ③ 需求优先级：事业 > 财运 > 感情

依据（外部数据，非本站数据）：

```
后浪研究所《2025 年轻人玄学消费报告》
  事业 76.5% / 财运 74.9% / 爱情 49.6%
一线从业者总结（于都杨公风水）
  「男问工作女问胎，平民百姓问发财，大龄女问婚姻来」
```

**所以自测分三套：工作 / 钱 / 感情**，顺序按这个排。

**砍掉了**「自己到底想干什么」（无数据支撑）和「家里的某件事」（非目标用户）。

## 四、哪些事 Agent 做不了，必须等人

| 事项 | 为什么 Agent 做不了 |
|---|---|
| **买域名**（`findmyi.app`） | 要身份证 + 支付 |
| **办个体户执照** | 要本人到场 |
| **签支付宝当面付** | 要执照 + 法人实名 |
| **发小红书 / 知乎** | 要账号和真人身份 |
| **在 GitHub 改仓库设置** | 虽然能通过 API 改，但涉及账号安全，建议人工确认 |
| **验证 Resend 发信域名** | 要 DNS 操作 + 邮箱验证 |

**所以「买域名 → 开邮箱登录」这条待办，卡的是人，不是技术。**

MiMo 如果推进到这里，应该停下来告诉用户「需要你去做这三步」，而不是自己想办法绕过。

## 五、当前最重要的商业判断

**这个项目现在缺的不是产品，是「有人愿意付钱」这个信号。**

```
内容：37 万字，完成
技术：付费墙 / 授权 / 账号 / 自测，全部跑通
变现：0 付费用户
```

**用户的原话背景**：他之前问「我怎么推广这个网站」。

**所以任何新功能的优先级判断标准是**：

> 这个改动，能不能让「第一个付费用户出现」更近一步？

能 → 做
不能 → 记下来，先别做

**举例**：
- 加微信登录 → 不能（要企业资质）
- 修目录页的付费引导 → 能（缩短决策路径）
- 做第 2 个站 → 不能（重复同一个错误）
- 优化支付流程 → 能（当前是人工确认，体验断点）
