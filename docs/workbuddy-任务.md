# WorkBuddy 任务：给 384 条处境打标签

> 复制下面整段给 WorkBuddy。它不需要其他上下文。

---

## 任务

读取本机文件：

```
D:\zhouyi-site\build\_ironrules.json
```

这是一个数组，共 **384 条**，每条结构如下：

```json
{
  "n": 1,
  "gua": "乾",
  "pos": "初九",
  "verdict": "你还在水底，就别急着冒头",
  "yao": "潜龙勿用",
  "situ": "你有想法，有本事，甚至比别人都强。可你现在的位置太低，说了没人听，做了没人跟。你憋得难受，觉得这是浪费。",
  "rule": "当你的名字在关键的那三五个人嘴里还排不进前三的时候，你所有的表态都是消耗品……",
  "exc": "如果这个团队或者这个行业明确处在抢位子的窗口期……"
}
```

**你要做的**：给每一条打 **1 个主标签 + 0–2 个次标签**，从下面 8 个里选。

---

## 8 个标签的定义

判断依据是 `situ`（用户描述自己处境的那段），不是 `yao`（爻辞）也不是 `rule`（建议）。

| 代码 | 标签 | 什么时候用 |
|---|---|---|
| `S1` | **想上去，上不去** | 位置低、能力有、没机会、说了没人听、憋屈、被压着 |
| `S2` | **刚被看见，站不稳** | 刚出头、刚被提拔、刚被注意到、根基浅、有人盯着 |
| `S3` | **卡在中间** | 承上启下、两头受气、最忙、背锅、不上不下 |
| `S4` | **到了高位，怕掉** | 已经成了、权力大、位置最高、怕失去、睡不着 |
| `S5` | **被打压，动不了** | 被排挤、被算计、被架空、明枪暗箭、动一下就错 |
| `S6` | **面临选择，不敢动** | 要不要做某事、两个选项选一个、决策关口、犹豫 |
| `S7` | **已经崩了，要重来** | 已经失败、损失已成、被裁、项目黄了、从头开始 |
| `S8` | **在等，什么也做不了** | 时机不到、被动等待、只能熬、无事可做 |

**判断优先级**（多条都像时按这个顺序）：

```
S7（已经崩了）> S5（被打压）> S6（要做选择）> S2（刚出头）> S4（高位）
> S3（卡中间）> S1（上不去）> S8（在等）
```

理由：已经发生的、被动的处境，比主动的选择更能定义「你现在在哪」。

---

## 输出格式

写一个 JSON 文件到：

```
D:\zhouyi-site\build\_situ-tags.json
```

结构（**保持原数组顺序**）：

```json
[
  { "n": 1, "pos": "初九", "gua": "乾", "main": "S1", "sub": ["S8"] },
  { "n": 1, "pos": "九二", "gua": "乾", "main": "S1", "sub": ["S2"] }
]
```

规则：

- `main` 必须是 `S1`–`S8` 之一，**不能为空**
- `sub` 是数组，**可以为空** `[]`，最多 2 个，且不能和 `main` 重复
- `n`、`pos`、`gua` 原样复制，不要改
- **必须 384 条一条不少**，顺序与源文件一致
- 用 UTF-8 无 BOM 保存

## 完成后自检并报告

跑完检查这 5 项，把结果写在回复里：

1. **总条数**：必须等于 384
2. **每类的条数**（main 标签的分布）：`S1:? S2:? S3:? S4:? S5:? S6:? S7:? S8:?`
3. **`main` 为空的条数**：必须是 0
4. **`sub` 里出现和 `main` 相同值的条数**：必须是 0
5. **你判断时最不确定的 5 条**：列出 `gua + pos + verdict + 你给的主标签 + 另一个候选标签`

---

## 质量要求

- **不要重新组织或改写原数据**，只加标签
- **不要跳过任何一条**，宁可给个次优标签也要填
- 判断卡住时，问自己一句话：**「这个人最难受的是什么？」** —— 選那个最接近的
- 如果某条确实和 8 类都不沾边，选最接近的，**并在第 5 项自检里点名**
