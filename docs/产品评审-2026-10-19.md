# 周易六十四卦站点 · 产品评审

> 评审时间：2026-10-19
> 评审对象：https://huangminzhe321-art.github.io/zhouyi/
> 方法：实际渲染截图 + DOM 测量 + 数据核对，不是凭印象

---

## 一、现在这个产品是什么

**一句话**：一个设计水准在线的《周易》解读站，免费部分做完了，付费部分建好了但卖不出去。

**客观数据**

| 项 | 数值 |
|---|---|
| 免费内容 | 15 篇前置（全免费）+ 64 卦的经文/白话/处世应用 = **52,860 字符** |
| 付费内容 | 64 篇逐爻深度解读 = **611,714 字符** |
| 免费 : 付费 | **8% : 92%** |
| 付费卡里给的样例 | 平均 **120 字符**（占单篇的 **1.3%**） |
| 定价 | ¥999 / ¥1999 两档终身买断 |
| 单篇文章页体积 | 平均 3 KB（纯片段，无 head） |
| 技术 | 静态站 + Cloudflare Worker 验码下发 |

## 二、三个致命问题

### 问题 1（最严重）：搜索引擎基本看不见这个站

**现象**

```
articles/qian.html   →  只有 3 KB 的 HTML 片段，没有 <html>、没有 <head>、没有 <title>
首页                  →  单页应用，路由是 #/p/qian（hash）
```

**后果**

| 项 | 状态 |
|---|---|
| 64 个「周易XX卦」长尾词 | **一个都抓不到** |
| 文章页 title | **无** |
| 文章页 description | **无** |
| 文章页 h1 | **0 个** |
| sitemap.xml | **无** |
| robots.txt | **无** |
| 结构化数据（ld+json） | **无** |
| og / twitter 卡片 | **无** |
| canonical | **无** |

**这意味着**：搜索引擎打开这个站，只能看到一个首页。64 篇正文在它眼里不存在。

**为什么致命**：内容站的自然流量 80–90% 来自搜索。「周易 乾卦」「乾卦 九五」这类词每天有稳定搜索量，但现在一条都吃不到。

**这不是优化项，是漏水的桶。** 花再多力气做内容，水都从这个洞流走。

**修法**：把 hash 路由改成真实路径（`/zhouyi/qian.html`），每篇生成完整 HTML（含 head、title、description、h1、canonical），加 sitemap 和 robots。工作量约 1–2 天。

---

### 问题 2：免费露出 8%，样例 1.3% —— 用户看不到就不敢买

**现象**

```
用户能免费看到的          52,860 字符（8%）
用户买到的               611,714 字符（92%）
付费卡里给的样例          120 字符（1.3%）

用户要滚 3,059 px（约 4 屏）才看到付费卡
```

**问题在哪**

付费卡承诺的是「逐爻拆解你所处的阶段、史书中的真实印证、判断方法」—— 这是产品的全部价值。

但用户在免费部分看到的只有：卦辞、彖传、大象传、爻辞、**一段**白话、**一段**处世应用。

**他看不到任何一段「逐爻拆解」，也看不到任何一条「史书印证」。**

等于：让他花 999 买一个从没见过的产品。

**行业参照**：知识付费产品的免费露出通常 15–30%，且必须包含**付费部分真实的样本**（不是概括，是原文截取）。

**修法**（按优先级）：
1. 每一爻至少放**一爻**的完整深度解读作为免费样本（约 600–800 字）
2. 免费样本要放在付费卡**之前**，不是卡里
3. 首页和目录页明确标出「哪部分是免费的、哪部分要买」

---

### 问题 3：首页入口按「知识结构」组织，不按「用户处境」

**现象**

首页 CTA 是「从卷首开始」「查看目录」，路径是：

```
卷首 3 篇 → 基础 7 篇 → 方法 4 篇 → 六十四卦
```

**这是教科书的组织方式，不是「我卡住了」的人需要的。**

**你自己的诊断**（之前的调研结论）：

> 「没人用『处境』当索引去调用历史案例库」—— 这是市场空位

但首页恰恰放弃了这个空位，回到了「先学阴阳八卦，再读六十四卦」的传统路径。

**一个真实用户的心理**：

```
他刚被降职 / 刚创业失败 / 正在纠结要不要辞职
他不会想「我要先学阴阳八卦」
他想「有没有人遇到过一样的事，他怎么办的」
```

**修法**：
1. 首页第一屏加一个入口：**「你现在遇到什么事？」** → 3–5 个处境选项（要不要辞职 / 被排挤 / 刚失败 / 要不要赌一把）→ 直接跳到对应的卦和爻
2. 「从卷首开始」降级为次要入口（给真正想系统学的人）

**成本**：384 条处境数据已经有了（`build/_ironrules.json`），只需要做一个匹配层。

## 三、几个中型问题

### 4. 「全解」这个标题与实际不符

网站叫「**六十四卦全解**」，但 92% 的内容是收费的。

用户点进来预期是「全部解答」，实际是「8% 的解答 + 92% 的付费墙」。

**建议**：副标题改成实话，比如「经文与白话免费，逐爻解读付费」，或者干脆换个名字（如「周易读本」）。

**理由**：预期落差在付费卡弹出的那一刻爆发，是流失最狠的位置。

### 5. 付费卡 1,909 px 高，信息过载

移动端需要滚 **4 屏**才能读完付费卡。里面有：

```
标题 + 副标题 + 价格锚点
两档对比（含 items / excludes / note × 2）
样例块
输码框
三条承诺
两个按钮
```

**问题**：用户在「要不要买」的决策点上，被塞了太多信息。

**修法**：砍到三块——**一句话价值 + 一个价格 + 一个按钮**。其他全部收进折叠。

### 6. 「已解锁？输入授权码」还在一级位置

现在有账号体系了（Google 登录，90 天免登录），授权码只剩「客服补发/赠送」这一个边缘场景。

但它现在和「立即购买」平级显示，**分散了主 CTA 的注意力**。

**修法**：降级成一行小字链接，点开才展开输入框。

### 7. 没有社会证明

整个站没有：

- 作者是谁（一句话都没有）
- 有多少人买过
- 任何一条用户反馈
- 内容被谁引用过

**卖 999 的东西，一个「谁在卖」都不交代，信任成本极高。**

**修法**：最少加两样——
1. 作者一段话（为什么写这个、读过什么、凭什么）
2. 3–5 条真实反馈（有了之后）

### 8. 文案 bug：14 篇 vs 15 篇

```
index.html:50   「先用 14 篇前置建立认知」
index.html:51   「前置 14 篇 · 卦辞 · 彖传…」
目录页标题        「先读前置 15 篇」

实际：卷首 3 + 基础 7 + 方法 4 + 参考书目 1 = 15 篇
```

**封面页少算了一篇。** 小问题，但会让人觉得「这站没人维护」。

## 四、做得好的地方

### 1. 视觉设计有水平

不是模板化的 AI 站：

| 元素 | 做法 |
|---|---|
| 字体 | 宋体做标题（Songti SC），不是全站无衬线 |
| 底色 | 宣纸色 `#fbf8f1`，不是纯白 |
| 强调色 | 朱砂红 `#a8322a`，用量克制 |
| 卦符 | 真的用六爻符号渲染，不是图片 |
| 跑马灯 | 卦名滚动条，有辨识度 |
| 细节 | 爻位序号用「初 / 二 / 三 / 四 / 五 / 上」而不是 1-6 |

**在同类传统文化站里，这个视觉水准属于上乘。**

### 2. 内容骨架有教学法

15 篇前置不是随便凑的：

```
卷首（3）  → 为什么读、怎么用、术语
基础（7）  → 阴阳、八卦、生成、爻位、错综互、成书、读法
方法（4）  → 占卜与决策、误区、常见问题、索引
参考（1）  → 书目
```

**这是一套完整的「先建立语言，再读文本」的路径**，不是把资料堆在一起。

对比：多数周易网站直接甩 64 卦，新手第一眼就懵。

### 3. 付费隔离是真的（这点很硬）

```
免费 52,860 字符 →  在 articles/*.html 里
付费 611,714 字符 →  在 Cloudflare KV 里，验码才下发
```

**静态产物里一个字的付费正文都没有。** 这条在个人站里很少见——大部分人是把全文写进 HTML 再用 CSS 遮住，F12 就破了。

配套的验证也做了：
- 篡改回调 → 验签失败
- 换设备 → 被拒
- 换设备但重新登录 → 能恢复

### 4. 细节完成度高

| 细节 | 说明 |
|---|---|
| 六爻爻辞按位排列 | 每爻带小象传 |
| 本篇目录 | 右侧 sticky，当前节高亮 |
| 阅读时间估算 | 「约 2 分钟」 |
| 关键词标签 | 每篇 4–5 个 |
| 上下篇导航 | 带卦符 |
| 字号/主题切换 | 有 |
| 打印样式 | 有 `@media print` |

## 五、如果只改三件事

按投入产出比排序：

### 第一件：改路由，让搜索引擎能看见（1–2 天）

```
现在：  #/p/qian  →  片段，无 title
改成：  /qian.html →  完整页面，有 title/description/h1/canonical/ld+json
加：    sitemap.xml（69 个 URL）、robots.txt
```

**这是唯一能把「内容」变成「流量」的动作。** 不做这个，后面所有优化都是在没人的店里换货架。

### 第二件：把免费露出从 8% 提到 20%，且必须是付费原文（半天）

```
每卦放 1 爻完整深度解读（约 600–800 字）到免费区
位置：付费卡之前
```

**理由**：用户买的是「逐爻拆解」，你得先给他看一爻。

### 第三件：首页加「你现在遇到什么事」入口（1 天）

```
5 个处境选项 → 每个对应 3–5 个卦爻 → 直接跳转
数据已有：build/_ironrules.json 里 384 条处境
```

**理由**：这是你自己诊断出的市场空位，但产品没接上。

---

## 六、一句话总结

**这是一个「做完了 80%，但缺的那 20% 恰好是让前 80% 被看见」的产品。**

内容生产、技术隔离、视觉设计都做到了中上水平，
但搜索引擎看不见它、用户看不到付费样本、首页没接上用户处境，
所以它现在是一个「没人知道的、卖不出去的、做得还挺好的」站。

**先修漏水的地方（SEO），再加免费样本，最后改首页入口。**
三个做完，这个产品才算真正「上线」。
