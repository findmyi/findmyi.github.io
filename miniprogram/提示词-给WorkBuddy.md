# 给 WorkBuddy 的提示词

> 直接复制下面整段粘贴给 WorkBuddy。

---

我要做一个**微信小程序**，参加 WorkBuddy「1024 造物挑战」。这是一个**简易版**，不要做复杂。

## 一、这个产品是什么

《周易》六十四卦的处境判断工具。

**核心逻辑**：用户答 12 道题 → 定位到「六个阶段」之一 → 给出最像他的 3 条处境 → 每条处境告诉他「你在哪、该做什么、什么情况下不适用」。

**这不是算命，是处境自测。** 全程不预测、不说吉凶运势。

## 二、数据已经准备好了，不要自己编

数据在 `D:\zhouyi-site\miniprogram\data\` 目录，三个文件：

### 1. `situations.js` — 384 条处境（308 KB）

```js
const { SITUATIONS, ofStage, ofGua, at } = require('./data/situations');
```

每条的结构（字段名已压缩）：

| 字段 | 含义 | 长度 | 示例 |
|---|---|---|---|
| `g` | 卦名 | 1 字 | 乾 |
| `p` | 爻位 | 2 字 | 初九 |
| `s` | 阶段 | P1-P6 | P1 |
| `v` | **判词** | 12 字 | 你还在水底，就别急着冒头 |
| `w` | **你在哪** | 61 字 | 你有想法，有本事… |
| `r` | **该做什么** | 98 字 | 当你的名字在关键的那三五个人嘴里… |
| `e` | **什么情况下不适用** | 65 字 | 如果这个团队明确处在抢位子的窗口期… |
| `y` | 爻辞原文 | 4 字 | 潜龙勿用 |

**可用的方法**：
- `ofStage('P2')` → 该阶段全部 64 条
- `ofGua('乾')` → 该卦六条（初爻到上爻）
- `at(0)` → 按数组下标取一条

**⚠️ 重要**：数据里**没有唯一 id 字段**。原始数据的 `n` 是「卦号 1-64」，每卦六爻共用同一个数字，**不能拿它当 key**（会互相覆盖）。要用对象本身，或者数组下标。

### 2. `quiz.js` — 题库 + 六阶段（19 KB）

```js
const { SCREEN, STAGES, COMMON, TRACKS, score, questionsFor, stageOf, TOTAL } = require('./data/quiz');
```

- `SCREEN` — 分流题，三选一（工作 / 钱 / 感情）
- `COMMON` — 8 道通用题
- `TRACKS` — 三套领域题，每套 4 道
- `questionsFor('work')` → 返回 12 题（8 通用 + 4 领域）
- `score(answers)` → 传入用户选中的选项数组，返回 `'P1'`~`'P6'`
- `stageOf('P2')` → 返回 `{code, name, ask, summary, advice, caution}`
- `TOTAL` = 12

**计分怎么用**：
```js
const qs = questionsFor('work');
const answers = [];   // 用户每答一题，push 一个选项对象 {t, s}
// 答完后：
const stageCode = score(answers);   // 'P3'
const stage = stageOf(stageCode);   // {name:'最难的中段', ask:'…', advice:'…', caution:'…'}
```

### 3. `picker.js` — 挑三条处境的算法（1 KB）

```js
const { pickThree } = require('./data/picker');
const picks = pickThree('P2');   // 返回 3 条处境
```

**直接用这个，不要自己写挑选逻辑。** 它已经处理了「尽量不同卦」「判词长度适中」两件事。

### 数据总量

```
328 KB —— 可以全量打进主包（上限 2 MB）
```

## 三、要做的页面（5 个，别贪多）

### 页面 1 · 首页

```
        你现在，在哪个阶段？

   12 道题，三分钟。
   答完给你三条最像你的处境。

         [ 开始测一测 ]
```

**不要放**：六十四卦列表、周易介绍、卦象图。**这个版本只要测试入口。**

### 页面 2 · 分流 + 答题

**先问一题分流**（用 `SCREEN`）：

```
你现在最想理清楚的，是哪一件事？

  ○ 工作上的位置，或者去留
  ○ 钱的事 —— 收入、投入、值不值
  ○ 和某个人的关系
```

**再答 12 题**（用 `questionsFor(track)`）：
- 一屏一题
- 顶部进度条 `3 / 12`
- 选项按钮，**点一下自动跳下一题**（不要「下一步」按钮）
- 左上角有返回上一题

### 页面 3 · 结果页（最重要）

- 「什么情况下不适用」— 黄色左边框 + 灰色字

## 四、技术要求

- **原生微信小程序**（WXML / WXSS / JS），不要用 uni-app、Taro、mpvue
- 不需要后端，数据全部本地
- 不需要用户登录、不要收集手机号
- 首页要能在 1 秒内出现

## 五、视觉风格（重要，别做成通用的蓝色科技风）

参考网站的视觉，是一套**宣纸 + 宋体 + 朱砂红**的东方美学：

```
底色      #fbf8f1   （宣纸白）
主文字    #1c1a17   （墨黑）
次要文字  #6b645a
强调色    #a8322a   （朱砂红）
分割线    #e8e2d8
```

- **标题用宋体**（`font-family: "Songti SC", serif`）
- 正文可以用系统默认
- 大量留白，不要塞满
- 圆角小一点（6-8px），不要大圆角
- 不要渐变、不要阴影堆叠

## 六、合规红线（必须遵守，否则会被下架）

**绝对不能出现的词**：
```
算命、占卜、预测、吉凶、运势、命、卦象解读、灵验、准不准
```

**必须用的说法**：
```
✅ 处境自测      ❌ 测卦
✅ 你现在处于什么阶段   ❌ 你的运势如何
✅ 这一条像不像你      ❌ 这一卦准不准
```

**产品定位一句话**：这不是算命，是一份处境的体检报告。

## 七、验收标准

做完后请自查：

```
□ 能完整走完：首页 → 分流 → 12 题 → 结果 → 三条处境
□ 三套题（工作/钱/感情）都能走通，且分别触发不同的题
□ 结果页的三条处境，卦名各不相同，爻位与阶段一致
   （P1 应是初九/初六，P2 应是九二/六二，以此类推）
□ 六十四卦列表能点进任意一卦，看到六条
□ 六爻按「上九在最上、初九在最下」排列
□ 全程没有一个字出现「算命/占卜/预测/吉凶」
□ 包体积小于 1 MB
```
