# 付费系统 · 站点所有者手册

> **免责声明**：本文是通用的**运营与合规参考**，不构成法律意见。
> 支付监管政策、平台费率与准入条件都会变化，请以你所在地区**当期**的
> 法规与平台公示条款为准。涉及金额较大的决策，建议咨询专业人士。

## 一、先读这一页（TL;DR）

这套系统做的事很简单：**把「原文 + 白话」免费给所有人看，把「深度解读」做成付费章节。**

它包含四块：

| 模块 | 作用 |
|---|---|
| 权益层 `Entitlement`（在 `assets/app.js` 内） | 判断「这篇文章现在能不能看完整版」 |
| 离线授权码 `assets/license.js` | 读者输入 `ZY-PREM-XXXX-XXXX-X` 即可解锁 |
| 授权码生成器 `build/gen-keys.mjs` | 你用它批量生成码，导出 CSV |
| 收款配置 `assets/payment.js` | 你填入平台链接，页面自动生成购买按钮 |

**最重要的一句话，请先记住：**

> 离线授权码是**混淆**，不是**安全**。
> 任何人打开 `assets/license.js` 都能自己造出一个"合法"的码。
> 真正保护你内容的是另一件事：**付费正文根本没有被打包进静态站点。**
> 详见第八节。

如果你只想先跑起来：跳到**第六节「五步上线」**。

## 二、合规第一：在中国大陆收款你必须知道的事

这一节请务必读完再动手。**合规问题比技术问题重要得多。**

### 1. 普通商户号需要营业执照

微信支付、支付宝的**普通商户**账户，开通时要求提供**营业执照**。
以个人身份无法直接开通具备"经营收款"性质的商户号。

### 2. 个人静态收款码不得用于经营性收款

中国人民银行 2022 年起施行的收款码相关规定明确：

- **个人静态收款码**（就是你在微信/支付宝里保存下来、打印出来或发出去的那张图）
  具有**远程收款**特征，被要求**限制用于经营活动**；
- 若确有经营需要，应当使用**商户收款码**（即"码"要绑定到有资质的经营主体）。

**也就是说：把个人收款码贴在网站上卖内容，是不合规的。**
这不是"金额小就没事"的问题——一旦被判定为经营行为且使用个人码，
账户可能被限制收款功能，且资金往来难以自证。

### 3. 唯一干净的个人路径：注册个体工商户

对个人创作者来说，**个体工商户**是成本最低、最合规的经营主体：

- 可以在各地**市场监督管理局**的线上平台申请，多数地区支持全程网办；
- 通常几个工作日可办结；
- 费用各地不同（有的地区免费，有的仅收少量工本费），**请以当地当期规定为准**；
- 办下来之后，你就可以用**自己的名义**去开通微信支付/支付宝商户号，
  或者入驻下面这些平台并提现到对公/对私账户。

> **建议节奏**：先用平台（下一节）跑通收款，同时去办个体工商户。
> 不要为了"快"而先用个人收款码，那是最容易出问题的做法。

### 4. 关于内容本身

本站的定位是**《周易》文本的现代解读**，这一点在付费卡上已经明确写出：

- 「不涉及占卜预测」——不提供算命、占卜、择日、改运；
- 「经文有据」——卦辞/彖传/象传/爻辞依据通行本《周易》，并列出参考书目。

**这不是公关话术，是护身符。** 官媒已公开批评过「国学直播乱象」——
以国学为名做占卜、卖高价课、贩卖焦虑。你在页面上的每一句
"不承诺结果"的声明，都是在把自己和那类内容区分开。
**请保持这个边界，不要为了转化率去加"改运""转运"之类的话术。**

## 三、收款平台怎么选

对个人创作者，优先用**第三方内容平台**——它们替你完成了收款、发货、对账，
你不需要自己有商户号。

| 平台 | 费率（约） | 最适合 | 需营业执照 | 自动发货 | 备注 |
|---|---|---|---|---|---|
| **面包多** mbd.pub | ~5% | 卖单篇文章 / 专栏 | 否 | ✅ 有 API | **个人首选**，最贴合本站形态 |
| **爱发电** afdian.com | ~6% | 会员制、连载更新 | 否 | ✅ | 适合按年/按月跟读 |
| **小报童** xiaobot.net | ~10% | 微信内阅读体验 | 否 | ✅ | 读者在微信里直接读，不用跳浏览器 |
| **Gumroad** | 10% + 通道费 | 海外读者 | 否（MoR 模式） | ✅ 有 License Key API | Stripe 不支持大陆主体，Gumroad 可以 |
| **Lemon Squeezy** | 5% + $0.50 | 海外读者 | 否 | ✅ | 同为 MoR，费率和 Gumroad 接近 |
| 手动发货 | 0（但有合规风险） | 极小规模测试 | — | ❌ | 见下方警告 |

> 费率会调整，**以上线时平台公示为准**。

### 推荐组合

1. **起步**：只开**面包多**。它自动发货、有 API，读者下单后立刻拿到授权码，
   你几乎不用做人工操作。
2. **加一层**：如果读者主要在微信里，再开**小报童**——
   微信内阅读体验明显优于跳转浏览器。
3. **出海**：有海外读者时加 **Gumroad**。

三个平台可以同时开启，页面上会按
面包多 → 爱发电 → 小报童 → Gumroad → 手动发货 的优先级依次显示按钮。

### 关于「手动发货」

`PAYMENT_CONFIG.manual` 用于"还没办好执照、想先小规模测试"的阶段：
读者加你微信，你人工发码。

**但要清楚它的风险**：如果这一步涉及用个人收款码收经营款，
就回到第二节说的问题了。建议**只作为过渡**，并且尽快转成平台收款。

## 四、⛔ 绝对不要用的平台

### 免签支付（码支付 / 虎皮椒 / 迅虎 / 蓝兔 等）

这类服务宣传"个人免签约收款""无需营业执照即可接入支付"。
它们的运作方式是：**让用户的付款先进入第三方的账户，再由第三方转给你。**

这在监管上叫**二次清算（二清）**，属于**无牌照从事支付结算业务**。

**具体风险：**

- **资金冻结**：你的钱在别人的账户里。对方跑路、被查、被冻结，你的钱一起没。
  这类平台出事时，创作者往往是最后知道的。
- **法律风险**：接入二清通道本身可能被认定为参与非法经营支付业务。
- **读者信任崩塌**：这类通道的收款页面体验粗糙，
  和本站的调性完全不符，会直接损害你辛苦建立的信任。
- **对账地狱**：没有正规凭证，出了问题无法追溯。

> **一句话：任何承诺"免签""个人也能接微信支付"的通道，都不要用。**
> 想收微信支付的钱，就用正规平台，或者办个体工商户去开正规商户号。

## 五、定价建议

当前配置（`assets/payment.js` 里的 `priceLabel`）是 **¥29**。这是一个刻意的选择。

### 为什么不做低价

在这个领域，**低价反而会降低转化**：

- ¥1–5 的价格会让人觉得"这东西大概没什么内容"；
- 更重要的是，它和你需要建立的**信任感**不匹配——
  专门骗人的那些内容通常标价很低然后走量；
- ¥29 是一个"认真读过、愿意为之付费"的门槛，
  同时又不至于让人需要犹豫很久。

### 为什么默认不做订阅

订阅适合**持续产出**的内容。本站是**已完成的、可校订的文本**——
读者买的是"读完这一篇"，不是"每月收到更新"。

**一次买断**还有一个好处：它在付费卡上直接对应一句承诺——
「不自动续费，不收集手机号，不发送营销信息」。
在信任稀缺的品类里，这句话的价值高于订阅带来的现金流。

（如果你后续做持续连载，再考虑用爱发电/小报童做会员，
两种模式可以并存。）

### 免费/付费怎么切

本站现在的切法是：

| 部分 | 是否免费 |
|---|---|
| 卦辞 · 彖传 · 大象传 | ✅ 免费 |
| 六爻爻辞 + 小象 | ✅ 免费 |
| 白话解读 | ✅ 免费 |
| 处世应用 | ✅ 免费 |
| **深度解读**（逐爻拆解、史例印证、自测法） | 💰 付费 |

**这个切法的逻辑**：免费部分回答"这一卦说了什么"，
付费部分回答"我现在该怎么做"。

读者拿到的是**完整的原文和基础解读**——他不会觉得被欺骗；
而"怎么用"这个最有价值、也最需要你个人功力的部分，才收费。

> **不要**把原文锁起来。那是公共领域的经典，
> 锁它既不合情理，也会立刻招来反感。

## 六、五步上线（操作清单）

### 第 1 步：办个体工商户

到当地**市场监督管理局**线上平台申请，经营范围写宽一些
（如"文化创意服务""信息咨询服务""出版物零售"等，按当地可选项目填）。

拿到执照后，你就可以开正规商户号，或者用于平台的实名提现。

### 第 2 步：注册平台并建商品

以面包多为例：

1. 注册并实名（个人实名即可，不需要执照）；
2. 后台创建商品，标题写清楚读者能得到什么；
3. 商品描述里**明确写**：虚拟内容、一次买断、不涉及占卜预测；
4. 开启**自动发货**，把发货内容设为"授权码：XXXX"（或引导读者到本站输入）；
5. 记下商品 ID（URL 里 `/o/` 后面那段）。

### 第 3 步：填写 `assets/payment.js`

打开 `assets/payment.js`，找到 `PAYMENT_CONFIG`，填入你的信息：

```js
mbd: {
  enabled: true,              // ← 改成 true
  productId: '你的商品ID',     // ← 填这里
  directUrl: '',              // 也可以直接粘完整链接（优先级更高）
  ...
},
```

同时可以调整：

```js
priceLabel: '¥29',           // 页面显示的价格
priceNote: '一次买断 · 永久可读 · 后续修订免费',
priceAnchor: '一杯咖啡的价格',  // 价格锚点，可留空
```

> 没填 `enabled: true` 的渠道不会显示。**先只开一个，跑通再加。**

### 第 4 步：写付费内容并构建

编辑 `content/premium-content.mjs`：

- `teaser` —— **公开**的引子，会写进 HTML，读者能看见；
- `depth` —— **付费**正文，**不会**写进静态产物；
- `sample` —— 付费卡上的样例（引一句 + 一小段 + 一句"后面还有多少字"）；
- `includes` —— 交付物清单，逐条显示在付费卡上；
- `tier` —— `'PREM'`（全站通行）或 `'QK00'`（乾坤专享）。

目前已有三篇示例：乾 `qian`、坤 `kun`、未济 `weiji`。
要标记更多卦为付费，在 `PREMIUM` 里加一条即可（key 用 manifest 里的文章 id）。

然后运行构建：

```bash
node build/build.mjs        # 生成 manifest / 搜索索引 / 正文
node build/test-paywall.mjs # 自检（60 项）
```

### 第 5 步：本地验证后发布

```bash
node serve.mjs 8848
# 浏览器打开 http://127.0.0.1:8848/#/p/qian
```

确认付费卡正常显示 → 生成一个测试码 → 输入验证能解锁 →
然后推送到 GitHub，Pages 会自动更新。

> **发布前务必跑一遍 `node build/test-paywall.mjs`。**
> 它会检查付费正文有没有意外泄漏到静态文件里。

## 七、生成与发放授权码

### 生成

```bash
# 生成 20 个全站通行码（默认）
node build/gen-keys.mjs

# 生成 100 个，标注批次
node build/gen-keys.mjs --n 100 --note "6月批次"

# 生成乾坤专享码（QK 是 QK00 的简写）
node build/gen-keys.mjs --tier QK --n 50

# 输出到指定文件
node build/gen-keys.mjs --out build/keys-june.csv

# 不写文件，直接打印 JSON（便于接脚本）
node build/gen-keys.mjs --n 10 --json
```

默认输出 `build/keys.csv`，列：

| 列 | 含义 |
|---|---|
| `key` | 授权码本体，如 `ZY-PREM-7K2M-9QX4-M` |
| `tier` | 等级：`PREM` / `QK00` |
| `issued` | 签发时间（ISO 8601） |
| `note` | 批次备注 |

### 等级说明

| 等级代码 | 名称 | 范围 |
|---|---|---|
| `PREM` | 全站通行 | 全部付费文章 |
| `QK00` | 乾坤专享 | 仅乾、坤两卦 |

> 等级代码**必须是 4 个字符**。授权码是按位置切分的，长度不齐会导致解析错位。
> 生成器接受 `--tier QK` 这种简写并自动补零。

### 发放

**推荐：平台自动发货。** 面包多/Gumroad 都支持把授权码作为发货内容自动发给买家，
买家付款后立刻拿到，你零操作。

**手动发放**只在早期或特殊情况下用。无论哪种方式：

- ⚠️ **`build/keys.csv` 不要提交到公开仓库。** 建议加进 `.gitignore`；
- ⚠️ **务必备份。** 码丢了就等于这些买家无法解锁；
- 建议按批次记录"这批码卖给了谁"，退款时好定位。

## 八、⚠️ 安全边界（务必读完）

这一节决定你对这套系统的期望是否合理。

### 它是混淆，不是安全

授权码的校验算法（FNV-1a 哈希取校验位）**完全公开**在 `assets/license.js` 里。
任何读者按 F12 都能读到这个文件，然后：

- 看懂算法；或者更省事的——
- **直接在控制台执行 `Entitlement.unlock('随便什么')`** 绕过前端判断。

**这是纯静态站点的物理限制。** 没有后端，就不可能在客户端藏住秘密。

### 它能挡住什么

- ✅ **顺手转发**：读者把链接发给朋友，朋友打开看到的是付费卡，不是正文。
- ✅ **搜索引擎**：付费正文没进 HTML，爬虫抓不到。
- ✅ **误以为可以随便看**：付费卡的存在本身就在提示"这里有价"。

### 它挡不住什么

- ❌ **任何会用 F12 的人**（几秒钟的事）。
- ❌ **授权码二次传播**：收到码的人可以再发给别人，离线校验无法察觉。

### 黄金法则：不要发布你想保护的东西

这套系统的安全性**不来自授权码**，而来自构建方式：

> 付费正文（`depth`）**根本没有被写进任何静态文件**。
> `articles/qian.html` 里只有公开的 `teaser`。
> 所以即使有人绕过前端校验，他拿到的也只是那段引子。

这一点由 `build/test-paywall.mjs` 强制验证——它会扫描全部静态产物，
确认 `depth` 里的每一个句子都不在其中。

**所以：如果你要加新的付费内容，一定写进 `content/premium-content.mjs` 的
`depth` 字段，而不是直接写进文章 HTML。** 写错了就等于免费公开了。

## 九、升级到服务端校验

当单篇内容的价值高到"用户可能愿意花时间破解"时，
或者你想**支持退款后吊销授权**时，就需要服务端校验。

**目标**：把「校验授权码」和「下发正文」都放到服务器，
前端只拿渲染结果。这样绕过前端就毫无意义。

### 用 Cloudflare Workers（免费额度足够）

模板已经写好：**`assets/paywall-worker.example.js`**（带完整注释）。

大致步骤：

1. 注册 Cloudflare（免费额度约 10 万次请求/天，个人站点绰绰有余）；
2. 新建一个 Worker，把模板代码粘进去；
3. 在 Worker 设置里加一个变量 `KEYS`，值是你已售出的授权码（逗号分隔）；
4. 把付费正文上传到 **R2**（对象存储）或 **KV**，键名形如 `premium/qian.html`；
5. 把前端 `assets/app.js` 里的 `article()` 改成向 Worker 发请求
   （模板顶部有现成的前端调用示例）。

### 用 KV 换取"可吊销"

模板里用环境变量 `KEYS` 是最简形式，但**无法吊销**——
码一旦生成就一直有效。

升级到 **KV** 后：

```bash
wrangler kv:namespace create KEYS
```

把已售出的码写进去，退款时**删掉那条记录**即可——
即使对方留着授权码，也拿不到内容了。

**到这一步，"绕过前端"才真正失效。**

## 十、常见问题

**Q1：读者说打不开付费内容 / 付费卡不显示。**
先确认 `data/manifest.json` 里有 `meta.premium.enabled: true`
且该文章的 `tier` 是 `"premium"`。如果字段缺失，前端会**优雅降级为全站免费**
（这是有意设计的，避免配置出错时把所有人挡在门外）。
另外确认 `index.html` 里 `license.js` 和 `payment.js` 在 `app.js` **之前**加载。

**Q2：读者说授权码输进去没反应。**
最常见是抄错字符。本站的字符表去掉了 `0 O 1 I L U` 这些易混字符，
所以正常不会出现"分不清 0 和 O"的情况。让读者确认：授权码共 15 位字符，
形如 `ZY-PREM-7K2M-9QX4-M`。输入框会自动补横线、自动转大写，
也接受粘贴带空格的文本。

**Q3：想改价格怎么办？**
改 `assets/payment.js` 里的 `priceLabel`（以及 `priceNote` / `priceAnchor`）。
注意**平台上的商品价格要单独改**——两边不一致会让读者困惑。

**Q4：想加新的付费文章。**
在 `content/premium-content.mjs` 的 `PREMIUM` 对象里加一条，
key 用该文章在 manifest 里的 id（如 `tai`、`pi`），
然后跑 `node build/build.mjs`。不需要改任何前端代码。

**Q5：有人在群里传播授权码怎么办？**
离线校验**无法阻止**这件事（见第八节）。
应对方式：① 一个码对应一个买家，记录在 CSV 里，发现异常传播就停止给该码提供售后；
② 升级到 Cloudflare Worker + KV，那样可以按码吊销；
③ 更根本的是——接受一定比例的泄漏，把精力放在持续产出上。

**Q6：读者要求退款怎么办？**
平台侧退款按平台规则走（面包多/Gumroad 都有退款流程）。
本站因为是一次买断的数字内容，建议在商品描述里提前写明退款政策。
退款后如果想收回访问权，需要服务端校验（第九节）——离线码收不回来。

**Q7：本站会不会被判成算命内容？**
这正是付费卡上那句「不涉及占卜预测」存在的原因。
**请守住这条线**：不承诺结果、不做预测、不卖"改运"服务，
保持"文本解读 + 史例分析"的定位，并持续维护参考书目。
同时**不要在营销文案里**用"转运""化解""改命"这类词——
页面合规但广告违规，一样会出问题。

**Q8：付费卡上的文案能改吗？**
能。文案在 `assets/app.js` 的 `paywallHtml()` 函数里。
`includes`（交付物清单）和 `sample`（样例）来自
`content/premium-content.mjs`，改那里即可。
**建议保留**三处内容：价格说明、交付物清单、"不涉及占卜预测"的声明——
它们直接对应读者最关心的三个疑虑。
