# 第一部分：怎么跑通付费

## 结论：技术上已经做完了，只差填 3 个空

你的站点**已经有完整的付费层**：

```
assets/payment.js      ← 四个平台适配（面包多 / 爱发电 / 小报童 / Gumroad）
assets/license.js      ← 授权码校验
assets/paywall.css     ← 付费卡样式
content/premium-guide.md ← 运营指南
```

**你现在只缺**：注册平台 + 填商品 ID + 生成一批授权码。

---

## 第 1 步：注册收款平台（约 30 分钟）

| 平台 | 适合 | 费率 | 个人能开 |
|---|---|---|---|
| **面包多** mbd.pub | **一次性买断**（你的情况） | ~5% | ✅ 身份证即可 |
| 爱发电 | 会员订阅 | ~6% | ✅ |
| 小报童 | 微信内阅读 | ~10% | ✅ |
| Gumroad | 海外读者 | 10% | ✅ |

**推荐先用面包多** —— 你是「一次性买断」，它的自动发货最顺。

## 第 2 步：建商品 + 填配置

在面包多后台建两个商品：

```
商品 1：周易六十四卦 · 终身会员      ¥999
商品 2：全站通 · 含孙子兵法与史料库   ¥1999
```

拿到商品 ID 后填进 `assets/payment.js`：

```js
mbd: {
  enabled: true,                    // ← 改成 true
  productId: '你的商品ID',
  // 或者直接贴完整链接
  directUrl: 'https://mbd.pub/o/xxx',
}
```

## 第 3 步：生成授权码

```bash
node build\gen-keys.mjs --n 200 --tier PREM
```

生成 200 个码，存到 `build/keys.csv`（已 gitignore）。

**然后把这批码填进面包多的「自动发货内容」** —— 买家付款后自动收到码。

## 第 4 步：验证

```
1. 自己买一单（或用测试码）
2. 在网站输入授权码
3. 确认付费内容解锁
```

---

## ⚠️ 一个你必须知道的技术限制

**现在的授权码是离线校验的，无法防转发。**

```
买家付款 → 拿到码 → 把码发到群里 → 别人也能用
```

**三个解法**（按成本排序）：

| 方案 | 成本 | 效果 |
|---|---|---|
| **A. 现在这样** | 0 | 防「顺手转发」，防不住故意分享 |
| **B. 一码一人**（记录已用） | 中 | 需要服务端 |
| **C. 内容加密 + 码即密钥** | 中高 | 纯静态，绕过前端也解不开 |

**你 999/1999 的定价，建议至少上 B** —— 因为客单价高，一个码被分享就是 999 的损失。

**B 的最简做法**：Cloudflare Worker + KV（免费额度够用），模板已在 `assets/paywall-worker.example.js`。

# 第二部分：定价优化

## 先说数据（来自两份调研）

### 中文市场的付费心理

| 数据 | 数值 |
|---|---|
| **知乎年 ARPU** | **¥114**（付费会员收入 15.39 亿 ÷ 1350 万会员） |
| 罗永浩/李一舟现象 | 头部价格锚点被拉到极端 |
| 站内实际成交带（咨询） | **¥300–600/小时** |

**关键**：知乎 ARPU ¥114 意味着**中文用户对「内容订阅」的心理价位极低**。

### 海外市场的定价锚点

| 平台/案例 | 定价 |

| Daily Stoic 课程 | $49–$499 |

### 转化率（决定你的算术）

**中位免费→付费转化率只有 0.62%**（每 1000 免费 ≈ 6 付费）。

## 你的定价，我算一遍

### 假设你的免费流量是真实的

```
假设能带来 10,000 个免费访客（长期累计）
× 0.62% 转化率
= 62 个付费用户
```

| 定价 | 62 人 | 收入 |
|---|---|---|
| ¥29 | | ¥1,798 |
| ¥199 | | ¥12,338 |
| **¥999** | | **¥61,938** |
| ¥1999 | | ¥123,938 |

**你的直觉是对的** —— 小众品类必须高客单，否则收不回成本。

### 但要面对一个现实

**转化率和客单价是反比的。**

```
¥29    →  转化率可能 2%+
¥999   →  转化率可能 0.1%
```

**所以真正的问题不是「定多少」，是「凭什么值 999」。**

---

## 我的建议：不要用「会员」，用「买断一套东西」

### ❌ 你现在的写法

```
999 元，终身网站会员，能看每一爻对应的情况与历史上的解法
1999 元，终身网站会员，能看孙子兵法和其他的相关的东西
```

**问题**：
1. **「会员」暗示持续服务** —— 你会被套住（要一直更新）
2. **「能看」是功能描述** —— 不是价值描述
3. **两档差距不清晰** —— 加 1000 元只多「孙子兵法」，说服力弱

### ✅ 改成「买断一套工具」

对照 John Brewton 的做法（$99/4 次一对一 → 后来变成 $15K 课程）：

```
¥999   《六十四卦困境对照表》· 终身买断
       —— 384 个处境 × 每个处境的铁律 + 历史解法

¥1999 全站通行 · 含孙子兵法、史料库、后续所有新增经典
```

**关键词从「会员」改成「买断」** —— 因为：
- 你的内容是**已完成**的（不是持续服务）
- 「终身」配合「买断」才成立
- 没有服务承诺，就没有服务压力

## 权益怎么写（这是最影响转化的部分）

### 原则：不要写功能，写「他会拿到什么」

| ❌ 功能描述 | ✅ 价值描述 |
|---|---|
| 「能看 384 条爻辞解读」 | 「你卡住的时候，能在 5 分钟内找到对应的处境和出路」 |
| 「包含历史案例」 | 「384 个历史上真实发生过的人，在同样的位置上怎么选的」 |
| 「终身更新」 | 「后续新增的经典（孙子兵法、史记精读）不再收费」 |

### 我建议的权益结构（999 档）

```
你会拿到：

✓ 384 个处境对照
  你现在遇到的情况，历史上都有人遇到过。按处境查，不用按卦查。

✓ 每个处境配三条东西
  · 这个处境到底在说什么（一句话）
  · 该做什么（带数字门槛的判断标准）
  · 历史上谁遇到过，他怎么选的，结果如何

✓ 一张自测表
  说不清自己卡在哪的时候，扫一遍就能定位。

✓ 一次 60 分钟一对一诊断（限前 100 名）
  我把你的具体情况，对到那 384 条里去。

✓ 后续所有修订免费
  内容会持续校订，已购的版本更新不再收费。

✗ 不包含：
  · 你想让我告诉你「辞还是不辞」，我不做这个判断
  · 算命、占卜、择日、改运 —— 本站不提供
```

**注意最后两条「不包含」** —— 这反而增加信任。

---

## 关于「一对一诊断」这个权益

**这是最重要的一条建议。**

你的 999 定价，如果只是「给内容」，说服力弱（内容容易被复制）。

**但加上「一次一对一」，就完全不同了**：

| | |
|---|---|
| 内容 | 可复制 |
| **一对一** | **不可复制，且对方能感受到价值** |

**而且它还有一个副作用**：你会拿到 100 个真实客户的**第一手数据** —— 这正是 John Brewton 用 400 小时教练时长反推课程的做法。

**999 里含一次 999 都值的诊断，用户会觉得赚了。**

## 在网站上怎么体现

**现在的付费卡结构已经支持**（`includes` 数组 + 价格行）。

**我建议加两个东西**：

### ① 价格对比锚点

```
¥999
一次一对一咨询的价格
（市面上 300-600/小时，两次就超过 999）
```

### ② 名额限制（真实施加，不要假造）

```

```

**注意**：只有你真的打算只做 100 个才写。**骗人的限量会毁掉信任。**

# 一句话总结

**定价不是问题，凭什么是问题。**

```
999 × 62 人 = ¥61,938    ← 数量上够
但要有人愿意付 999         ← 这才是问题
```

**解法**：把「会员」改成「买断」+ 加一次**不可复制的一对一** + 写清**不包含什么**。
