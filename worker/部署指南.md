# 部署指南 · 从零到收款

> 目标：让付费墙真正能用 —— 用户付款 → 拿到授权码 → 输码看到正文。
>
> 全程约 **1 小时**，成本 **0 元**（Cloudflare 免费额度足够）。

---

## 为什么需要服务端

**这是整个付费体系的生死线。**

```
付费正文放静态站  →  等于免费公开（F12 就能看）
付费正文不放      →  用户解锁后看不到内容
```

**唯一解法**：正文存服务端，**验码之后才下发**。

```
静态站（GitHub Pages）
  └─ 只有免费内容 + 付费卡（没有正文）

Cloudflare Worker + KV
  ├─ 存付费正文
  └─ 验码 → 下发正文
```

**这就是为什么不能只挂个收款码** —— 收款码没有回调，也没有地方存正文。

## 第一步：部署 Worker（20 分钟）

### 1.1 注册 Cloudflare

https://dash.cloudflare.com/sign-up

### 1.2 建 KV 命名空间

控制台左侧 → **Storage & Databases** → **KV** → **Create namespace**

名字填：`ZHOUYI`

### 1.3 建 Worker

左侧 → **Workers & Pages** → **Create** → **Worker**

名字填：`zhouyi-api`

把 `worker/index.js` 的**全部内容**粘进去 → **Deploy**

### 1.4 绑定 KV 和管理员密钥

进入 Worker → **Settings** → **Bindings**：

| 类型 | 变量名 | 值 |
|---|---|---|
| **KV Namespace** | `KEYS` | 选 `ZHOUYI` |
| **Secret** | `ADMIN_TOKEN` | 自己设一个随机串（如 `zysite-2026-abc123`，**记住它**） |

⚠️ 变量名必须**一字不差**：`KEYS`、`ADMIN_TOKEN`

### 1.5 拿到 Worker 地址

形如：`https://zhouyi-api.你的用户名.workers.dev`

**测一下**：浏览器打开 `地址/health`，应该返回 `{"ok":true,...}`

## 第二步：灌付费正文（10 分钟）

### 2.1 本地导出

```powershell
cd D:\zhouyi-site
python build\export-content.py
```

会生成 `worker/content-kv.json`（64 篇，约 1.4 MB）。

### 2.2 装 wrangler 并登录

```powershell
npm i -g wrangler
wrangler login
```

### 2.3 批量写入 KV

```powershell
cd D:\zhouyi-site
wrangler kv bulk put --binding=KEYS worker/content-kv.json --remote
```

⚠️ 如果提示要 namespace id，改成：

```powershell
wrangler kv bulk put --namespace-id=你的KV_ID worker/content-kv.json --remote
```

（KV ID 在 Cloudflare 控制台的 KV 页面能看到）

### 2.4 验证

Cloudflare 控制台 → KV → `ZHOUYI` → 应该看到 **64 条** `content:xxx` 开头的键。

## 第三步：生成授权码（5 分钟）

用管理员接口批量生成：

```powershell
curl.exe -X POST https://zhouyi-api.你的用户名.workers.dev `
  -H "content-type: application/json" `
  -d "{\"action\":\"issue\",\"token\":\"你的ADMIN_TOKEN\",\"count\":200,\"tier\":\"PREM\"}"
```

返回 200 个授权码，形如 `ZY-PREM-7K2M-9QX4-M`。

**把这批码保存下来**（这就是你要卖给用户的东西）。

### 看一眼统计

```powershell
curl.exe -X POST https://zhouyi-api.你的用户名.workers.dev `
  -H "content-type: application/json" `
  -d "{\"action\":\"stats\",\"token\":\"你的ADMIN_TOKEN\"}"
```

返回：总数 / 已用 / 未用 / 已吊销

### 吊销一个码（退款或泄露时）

```powershell
curl.exe -X POST https://zhouyi-api.你的用户名.workers.dev `
  -H "content-type: application/json" `
  -d "{\"action\":\"revoke\",\"token\":\"你的ADMIN_TOKEN\",\"key\":\"ZY-PREM-7K2M-9QX4-M\"}"
```

## 第四步：填进站点（2 分钟）

打开 `assets/payment.js`，找到：

```js
workerUrl: '',
```

改成你的 Worker 地址：

```js
workerUrl: 'https://zhouyi-api.你的用户名.workers.dev',
```

然后重新构建 + 部署：

```powershell
node build\build.mjs
git add -A
git commit -m "接入服务端授权"
git push
```

## 第五步：自测（5 分钟）

```
1. 打开线上站点，进任意一卦
2. 复制一个授权码，粘贴到「输入授权码解锁」
3. 应该看到：解锁成功 + 正文出现
4. 换一台设备/浏览器，用同一个码再试
   → 应该被拒绝（提示「已绑定到另一台设备」）
```

**第 4 步是关键** —— 它证明「一码一人」生效了。

## 收款怎么办

**现在你有了完整的授权系统，收款反而简单了。**

三个选择：

| 方式 | 怎么做 | 优缺点 |
|---|---|---|
| **A. 人工收款**（推荐先这样） | 买家微信/支付宝转账 → 你手动发一个码 | **立刻能用**，你能看到每个买家 |
| **B. 爱发电** | 上架数字商品，自动回复里贴码 | 官方文档确认支持自动发码；费率 6%；**次月 1 号结算** |
| **C. 小微商户**（XorPay 类） | 持牌服务商代签微信/支付宝官方支付 | 有 API 回调可全自动，费率约 1.2%，**合规** |

**建议顺序：A → 有单了 → B 或 C。**

理由：**你现在一单都没有**，自动化是多余的。人工收款能让你看到真实买家是谁、为什么买。

---

## ⚠️ 三个不要做

1. **不要用「免签支付」**（码支付/虎皮椒/迅虎等）
   2025 年有判例：搭免签系统给别人用、沉淀他人资金 → **非法经营罪，判四年**。
   自己卖自己的东西、挂自己的收款码、人工确认 —— 这个不构成支付业务。

2. **不要用「个人收款码 + 前端生成码」**
   码在前端生成 = F12 就能看到逻辑 = 等于免费公开站。

3. **不要把正文放进 `articles/` 或 `data/`**
   那等于免费公开。正文只能放 KV。

## 日常运维

| 事项 | 怎么做 |
|---|---|
| **看卖了多少** | `stats` 接口 |
| **码不够了** | `issue` 接口再生成一批 |
| **有人退款** | `revoke` 吊销他的码 |
| **买家换设备** | 目前码绑设备，换机需你手动处理（未来可加"换绑"接口） |
| **改正文** | 改 `content/v3/*.md` → 跑 `md2premium.py` → `export-content.py` → 重新 bulk put |
